# Support Ticket Index

The Apex Services Lab environment was used to simulate 16 completed IT Support and Microsoft 365 support tickets.

Each ticket represents a specific user request or support issue investigated within the lab.

The scenarios follow an evidence-based support process:

User Request → Investigation → Diagnosis → Resolution → Verification

## Ticket Documentation

Each ticket documents the relevant support activity using the information available from the actual lab environment.

Depending on the scenario, the evidence may include:

- User or service baseline
- Configuration state
- Controlled failure
- Technical diagnosis
- Corrective action
- User-facing test
- Restored state

The screenshots are used as supporting evidence rather than as a replacement for the technical explanation.

## Support Scenarios

### Exchange & Email

Tickets 1–3, 8–9, and 13 cover common Exchange Online support situations involving permissions, distribution groups, aliases, automatic replies, forwarding, and mailbox lifecycle management.

### User Administration

Tickets 4–6 and 14 cover common Microsoft 365 user-lifecycle tasks including onboarding, password reset, licensing, and offboarding.

### Outlook & Collaboration

Tickets 7, 10–12, and 15 cover calendar delegation, Outlook Mobile, SharePoint, room booking, and Teams access.

### Endpoint Management

Ticket 16 demonstrates troubleshooting a Windows device compliance failure using Microsoft Intune.

### Evidence Based Troubleshooting

The tickets were performed within the controlled Apex Services Lab environment.

Where a failure was required, a working configuration was intentionally changed to reproduce the problem. The issue was then investigated and corrected.

The final state was verified through the relevant Microsoft 365 service, administrator interface, or user-facing test.

This provides evidence of the complete support process rather than simply documenting a successful configuration.
